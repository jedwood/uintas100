# Plan: CMA book — compressed PDF link-out + inline photos

Goal: let Jed jump from the app's text-only book view to Cordell Andersen's
actual pages (photos included), two ways, so he can later decide whether the
HTML-with-photos alone is good enough to drop the PDF link entirely.

## Context you need (read this, skip the archaeology)

- Source PDF: `data/the-high-uinta-mountains-by-cma.pdf` — 148MB scan of the
  713-page self-published book, **gitignored, exists only on the Mac Mini**
  (this machine, host `olaf`). Full embedded text layer; never OCR.
  **Printed page N = PDF page N + 15** (uniform; index = PDF pages 700–713).
- `cma_book.html` (repo root, ~1.3MB) is the full book as HTML, one
  `<section class="cma-page" id="cma-pNNN">` per printed page. Generated by
  `scripts/export_cma_book.py` (idempotent; re-run any time). The PWA's lake
  modal fetches it and shows an in-modal viewer: see `openBookPage()` /
  `revealBookPage()` / `#book-view` in `index.html`. Citations `*(p. NNN)*`
  in `cma_notes` are links into it.
- The Mini already runs `tailscale serve --bg localhost:8802` proxying the
  edits server to `https://olaf.tailbf6340.ts.net` (config persists across
  reboots). The iPhone PWA syncs through that URL. **Do not break the
  existing :8802 proxy** — `tailscale serve` path mounts merge, so add a
  path, then verify `curl https://olaf.tailbf6340.ts.net/api/ping` still
  works.
- Copyright note: the author is alive and local. The compressed full-book PDF
  scan stays **out of the public github.io repo** (gitignored, same as the
  source PDF) — but on 2026-08-12, after comparing the HTML-with-photos
  rendering against the PDF on the Mini, Jed decided the extracted page
  photos (cropped/resized, not full-page scans) are fine to commit alongside
  `cma_book.html`, and that the Tailscale PDF deep-link (Task 2) isn't needed
  — the HTML view alone is good enough.

## Task 1 — Ghostscript-compress the PDF

```bash
gs -sDEVICE=pdfwrite -dCompatibilityLevel=1.5 -dPDFSETTINGS=/ebook \
   -dNOPAUSE -dBATCH -o data/cma-book-web.pdf data/the-high-uinta-mountains-by-cma.pdf
```
- Try `/ebook` (150dpi) first; if quality is rough on photo pages, retry with
  explicit `-dColorImageResolution=200`. Target well under 100MB.
- **Verify page count is still 713** (`pdfinfo`) — the `#page=` links depend
  on the printed↔PDF page mapping surviving.
- Add `data/cma-book-web.pdf` to `.gitignore` next to the source-PDF entry.

## Task 2 — Serve it over Tailscale + link from the book view

- Mount it: `tailscale serve --bg --set-path /cma-book.pdf \
  /Volumes/OLAF-EXT/jedwoodx/repos/uintas/data/cma-book-web.pdf`
  (syntax may differ by tailscale version — check `tailscale serve --help`;
  if file mounts aren't supported, serve the file from a tiny static server
  on a spare port and proxy that path). Confirm the :8802 proxy still works.
- In `index.html`, add an "Open scanned book (photos)" link:
  - in the `#book-view` sticky header, and
  - per page section is unnecessary — one link that targets the *currently
    viewed* page is better: track the last page passed to `openBookPage()`
    and set `href = 'https://olaf.tailbf6340.ts.net/cma-book.pdf#page=' +
    (printedPage + 15)`, `target="_blank"`.
- Known limits to note in the link title/tooltip, not to fight: `#page=`
  works in desktop browsers' PDF viewers; **iOS Safari ignores it** (opens
  page 1); the link only works while Tailscale VPN is on.

## Task 3 — Extract photos, optimize, inline into the HTML

- Survey first: `pdfimages -list data/the-high-uinta-mountains-by-cma.pdf`
  → which PDF pages carry raster images, their sizes. Expect many pages;
  filter out tiny/decorative images (< ~200px either dimension).
- Extract embedded images (`pdfimages -j -f N -l N`) rather than rasterizing
  whole pages — pages are text+photo composites and full-page renders would
  duplicate the text. If the scan turns out to be full-page images (every
  page one big JPEG), fall back to NOT inlining everything and reconsider
  scope with Jed.
- Optimize for web: longest edge ~1000–1200px, JPEG quality ~70 (`sips` is
  on macOS; ImageMagick fine too). Output `cma_photos/p<printed>-<i>.jpg`.
  **Report the total size before wiring anything** — hundreds of MB changes
  the plan (maybe photos stay Tailscale-hosted instead of in-repo).
- Extend `scripts/export_cma_book.py` to append `<img loading="lazy"
  src="cma_photos/pNNN-i.jpg">` tags to each page's section. `loading="lazy"`
  is mandatory — the modal injects all 700 sections at once and must not
  fetch every photo. Do NOT add photos to the service-worker precache; the
  existing runtime cache handles viewed images (iOS cache cap is 45MB — see
  `MAX_CACHE_SIZE` in `service-worker.js`).
- `cma_photos/` is committed to the repo (see copyright note above,
  2026-08-12 decision).
